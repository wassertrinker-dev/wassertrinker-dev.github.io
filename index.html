So entsteht eine Änderung

Von der Idee zur Veröffentlichung.

Ein nachvollziehbarer Prozess: Erst wird die Story gemeinsam geschärft, danach folgt die kontrollierte Auslieferung.

  1. Story Writer AgentEin Mensch und der spezialisierte Story Writer Agent besprechen die Idee. Entwurf und Akzeptanzkriterien werden so lange geschärft, bis der Mensch „Story freigeben“ sagt.
  2. GitHub Issue erstellenErst nach der Freigabe wird der Entwurf zur verbindlichen User Story.
  3. Nächsten Schritt wählenEs können weitere Stories mit dem Story Writer vorbereitet werden – oder die Umsetzung einer freigegebenen Story beginnt.
  4. Lead Agent implementiertWährend der Umsetzung arbeitet genau ein Agent schreibend auf dem Story-Branch. Danach folgen Test und notwendige Dokumentation.
  5. Pull Request erstellenDie geprüfte Änderung wird mit der verbindlichen Story verknüpft und zur Abnahme bereitgestellt.
  6. Fünf Agenten prüfen parallelUX, Architektur, Codequalität, Security sowie Tests und Dokumentation untersuchen den Pull Request unabhängig und gleichzeitig. Ihre Ergebnisse werden zu GO oder NO-GO zusammengeführt.
  7. Bei NO-GO nachbessernBlockierende Befunde gehen zurück an die Umsetzung. Nach Korrektur und Test läuft das Merge Gate erneut.
  8. Menschlich freigeben und veröffentlichenNur nach ausdrücklicher Freigabe wird nach main gemergt; GitHub Pages veröffentlicht daraus die Seite.
